# Node and Launch Benchmarking Workflow

Use for every named marketing node, product launch, press event, holiday campaign, promotion, or other important communication requirement. It makes the proposal comparable to the named client's history, industry practice, and competitors without fabricating cases.

## Inputs and fallback

First check whether the brief supplies: client/brand name, industry and segment, target market, named competitors, relevant previous client campaigns, public case links or files, campaign date, objective, channel, execution, and available result data.

If any core input is absent, output this issue card before benchmarking:

```
### 【缺失】客户/行业/竞品同节点对照资料
- 当前无法确认：client name / industry / market / competitors / prior campaign evidence.
- 会影响：cannot judge whether a proposed mechanism is differentiated, repeatable, risky, or already overused.
- 建议向客户或客户对接人员补充：brand name and product, target market, 3–5 competitors, prior same-node/launch/press-event/promotion materials, public links, dates, objectives, channels, actual results and constraints that may be used in the proposal.
- 在资料到位前：provide a labeled generic mechanism only; do not attribute it to the client, industry, or competitor.
```

## Research and comparison

When inputs are available, compare by the **same task type**, not merely by the same calendar date:

1. Client's prior same-node, product-launch, press-event, holiday, or promotion work.
2. Industry peers in the same market and segment.
3. Named competitors' comparable work.
4. Relevant public cases only when their date, source, and scope are clear.

For each source, label `【客户历史】`, `【同行业】`, `【竞品】`, or `【公开参考】`; distinguish documented facts from inference. Never treat a public case's delivery metric as the client's likely result.

## Output per node/launch

Use this compact comparison block inside every Node & Launch Coverage Matrix row or card:

```
【同节点/重要传播对照】
- 客户历史：what was done, objective, result boundary, and reusable/non-reusable learning.
- 同行业：comparable mechanism, why it works, and saturation risk.
- 竞品：observable choice, differentiation gap, and the response decision.
- 本次取舍：what to borrow, avoid, or deliberately differentiate.
- 证据与限制：source/date and unknowns.
```

The output should answer “why this gameplay for this client now?” rather than list unrelated awards or generic case names.
