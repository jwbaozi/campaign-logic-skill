# Closing Review v2.9

## Purpose

用于帮助 AI Marketing Strategy Skill 对营销项目结案进行系统复盘。

除评估项目结果、执行效果和经验沉淀外，增加：

-   策略方法论复盘
-   呈现模型复盘
-   可复用资产沉淀

**交付规则：** 对任何实质性“结案”“复盘”“结案测试”请求，先给简明聊天结论，再**必须**生成 Markdown 审计报告与自包含 HTML 审计报告。不能以仅输出文字审计结论视为完成；HTML 报告按 `workflows/visual-report.md` 的生成器制作。

# Review Dimensions

## 1. Objective Review

检查：

-   项目目标是否达成
-   指标是否与目标一致
-   实际结果与预期差异

------------------------------------------------------------------------

## 2. Execution Review

检查：

-   执行是否符合策略规划
-   平台、资源、内容是否有效协同
-   执行过程中出现的问题

------------------------------------------------------------------------

## 3. Data Performance Review

检查：

-   数据表现
-   核心指标变化
-   用户反馈
-   投放效果

区分：

-   项目实际数据
-   平台数据
-   行业参考数据

------------------------------------------------------------------------

# 4. Strategy Methodology Review

复盘：

## Methodology Effectiveness

检查：

-   使用的方法论是否有效支持策略制定
-   方法论是否帮助发现关键问题
-   是否需要替换更适合的分析框架

# Mandatory Closing Audit Report

报告沿用营销方案诊断报告的阅读顺序，并将下列内容作为必填项：

1. 标题、原始材料、生成日期与【事实边界】
2. 总体判断，以及【可保留】、【薄弱】、【断层】、【冲突】、【缺失】等分类结论
3. 可复用方法论及对应视觉资产（适用时）
4. 建议的呈现模型及对应视觉资产（适用时）
5. 执行与 KPI：目标、动作、责任、验收口径与下一阶段安排
6. 证据台账：原始主张/数据、页码或来源、数据分级、可支持结论与待补证据
7. 问题卡：原始位置、判定、为什么、影响、修订动作与可直接替换内容
8. 整改路线、对外可用表述、【缺失】客户/行业/竞品资料及向客户对接人的补充请求
9. 多角色审视提问

对每项结果数据明确标为【项目传播数据】、【平台数据】、【内部数据】、【行业参考】或【待核验】。将规划目标、历史结果与本期结果分开呈现；来源、基线、统计窗口或归因不足时，不下达成、美誉度或商业增长的确定性结论。

生成顺序：先完成 Markdown 审计源稿，再调用 `scripts/generate_visual_report.py` 生成同名 HTML 文件；交付前检查两个文件存在，检查报告包含上述九项，并在聊天中给出两个文件路径。
