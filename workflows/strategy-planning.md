# Strategy Planning Workflow v2.4

## Use when

Use when a user asks to create a marketing strategy, campaign plan, launch plan, annual plan, or growth path from available inputs.

## Flow

`business goal → commercial problem → north-star and sub-goals → market/competition/audience evidence → need/barrier/motivation/context → insight → strategic choice → Core Idea → communication/conversion path → phased execution → KPI, experiment, and review`.

Explain why every step permits the next. Mark unavailable facts as `【需要补充】` and planning placeholders as `【示例假设】`; give a validation route instead of presenting assumptions as facts.

## Routing

- Use `workflows/knowledge-routing.md` for the smallest knowledge set that affects the decision.
- Use a methodology only if it changes a decision; report why it fits, what it concludes, and how that conclusion changes the next step.
- Use `logic/execution_planning_engine.md` for all actions that must occur in market.
- For a launch, holiday, node, promotion, anniversary, event, or hot topic, also use `workflows/campaign-idea-planning.md`.

## Planning requirements

For annual planning, start from business strategy, external change factors, marketing objectives, north-star and sub-metrics, paths, resource allocation, and a month-by-month node/calendar view. For product lifecycle work, vary audience, content, search, creative, and private-domain strategy by introduction, growth, maturity, or renewal stage. For launches, connect public, commerce, and private channels; include only the appropriate roles for brand account, creator, user content, media, livestream, and commerce handoff.
