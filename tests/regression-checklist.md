# 回归测试清单

每次修改后逐项检查：

- [ ] 是否识别用户角色
- [ ] 是否识别材料成熟度
- [ ] 是否识别方案类型
- [ ] 是否先给整体判断
- [ ] 是否只问关键问题
- [ ] 是否接受“暂时拿不到”
- [ ] 是否区分客户版和内部判断
- [ ] 是否区分项目数据和参考数据
- [ ] 是否避免编造
- [ ] 是否给出可执行建议
- [ ] 是否正确生成知识库检索词
- [ ] 是否在 ima 不可访问时提供替代来源
- [ ] 是否在用户需要时生成可编辑 PPT
- [ ] 是否提炼当前最需要修正的逻辑
- [ ] 是否形成一句话总策略
- [ ] 是否按总策略主线重排页面
- [ ] PPT 是否使用原生可编辑元素
- [ ] 是否将内部敏感内容与客户版分开
- [ ] 是否先声明方案可判断范围与无法确认项，且仍继续分析
- [ ] 是否沿 Brief→商业问题→目标→洞察→策略→Core Idea→执行→KPI 检查因果链
- [ ] 每个关键问题是否含原文、分类、原因、后果、修改和可直接使用示例
- [ ] 是否正确使用【缺失】【薄弱】【断层】【冲突】【空泛】【不可落地】【可保留】分类
- [ ] 是否只在能改变判断时调用方法论，并说明其结论如何进入下一步
- [ ] 节点/上市/大促是否先判断品牌相关性、用户变化和目标动作
- [ ] 节点创意是否至少给出三条机制不同的路线（用户未要求简版时）
- [ ] 每条创意是否包含参与、内容、扩散、角色、承接、投放、KPI、难度与风险
- [ ] 是否把策略或创意拆为 Strategy→Action→Tactic→Deliverable→Owner→Timing→Channel→KPI
- [ ] 是否写清预热/引爆/持续/转化/沉淀的用户动作、品牌动作、内容、投放与承接（适用时）
- [ ] 是否将KPI与具体动作一一对应，并提供复盘或下一轮测试方式
- [ ] 目标/KPI 修复时，是否在适用时推荐并嵌入 SMART 方法论图片
- [ ] 方案结构或节点时间规划时，是否推荐并嵌入适用的策略呈现图
- [ ] 教师节是否提供机制不同的玩法、敏感性边界与非礼品压力的参与路径
- [ ] 当下热梗是否经过带来源和抓取日期的即时扫描，而非使用模型记忆
- [ ] 热梗方案是否提供品牌安全判断与不依赖热梗的替代路线
- [ ] 可视化报告是否只重排已经验证的 Markdown 内容，且没有虚构图表或数据结论
- [ ] 文字诊断和可视化报告完成后，是否询问用户是否需要多角色审视
- [ ] 多角色审视是否在用户确认后才执行，且角色被描述为审视镜头而非真实人员意见
- [ ] 每个角色是否覆盖决策标准、追问、风险、确认项和建议动作
- [ ] 多角色结果是否合并为提案前决策、上线前验证和上线后优化清单
- [ ] 是否先提取并列出材料中全部节点、上新和重要传播要求，而非只扩展某一个示例
- [ ] 每个节点/上新是否都有直接玩法、承接、KPI、风险和趋势状态
- [ ] 未来节点是否设置 T-14 至 T-7 趋势扫描窗口，而非复用今天的热梗
- [ ] 未来节点是否使用“在实际发布前 T-14 至 T-7 重新扫描并做平台、权益与品牌安全核验”完整表述
- [ ] 每个节点/上新是否有客户历史、同行业、竞品与公开参考的对照，或明确的【缺失】与补充请求
- [ ] 客户/竞品案例是否标注来源、日期和事实边界，且没有把案例结果写成客户预期
